## 2026/01/01 午後 - ユーザーテストでのUX改善

### 概要

色んな人にテストしてもらい、実際のユーザーフィードバックを基に大幅なUX改善を実施しました。

---

### ユーザーからの声

**問題点**:
1. 「誰に共有するの？」← 共有先が不明確
2. 「タイトルが見切れる」← スマホで長いタイトルが表示しきれない
3. 「グレーのボタンが戻るボタンに見える」← ボタンの役割が不明確
4. 「共有ボタンが画面下に隠れてる」← スクロールしないと見えない
5. 「最初から共有ボタンがあるのは変」← まだ占ってないのに
6. 「10個だとすぐ同じのが出る」← バリエーション不足

---

### 実施した改善

#### 1. 共有先の明確化

**問題:**
- ただ「共有」だけだと誰に送るのか分からない

**解決:**
- ボタンテキストを「公式アカウントに共有」に変更
- 公式LINEのプロフィール画像アイコンを追加
- 視覚的に共有先が明確に

**コード変更:**
```html
<button class="share-button" id="shareButton" onclick="shareToLine()">
    <img src="images/line-profile.jpg" alt="プロフィール" class="profile-icon">
    <span>公式アカウントに共有</span>
</button>
```

**CSS:**
```css
.share-button {
    display: flex;
    align-items: center;
    gap: 10px;
}
.profile-icon {
    width: 32px;
    height: 32px;
    border-radius: 50%;
}
```

#### 2. 運勢タイトルの短縮

**問題:**
- 最長24文字のタイトルがスマホで見切れる
- 「今年の」など冗長な表現が多い

**解決:**
- 全タイトルを10〜14文字に短縮
- 「〜そう」「〜ありそう」で運勢感を統一
- 「今年の」などを省いて簡潔に

**変更例:**
| 変更前 | 文字数 | 変更後 | 文字数 |
|--------|--------|--------|--------|
| たくさんのアイスに出会えるでしょう | 19文字 | アイスにたくさん出会えそう | 14文字 |
| どうでもいいことで笑うことがたくさんありそう | 24文字 | どうでもいいことで笑える | 12文字 |
| コンビニでお気に入りの商品に出会える | 20文字 | コンビニで素敵な出会い | 11文字 |
| 寄り道した先で楽しい時間が見つかる | 19文字 | 寄り道先でいいことありそう | 14文字 |

#### 3. ボタンデザインの改善

**問題A: 占うボタンがグレーで戻るボタンに見える**

**解決:**
- グレー (#888) → 落ち着いたベージュ (#D4C4B0) に変更
- padding: 18px 50px → 25px 70px（さらに大きく）
- font-size: 1.1em → 1.35em
- font-weight: 500 → 700（太字で目立つ）

**問題B: 占うボタンと共有ボタンのメリハリ不足**

**解決:**
- 占うボタン: font-weight 700（メインとして強調）
- 共有ボタン: font-weight 500（サブとして控えめ）
- 共有ボタンを小さく: padding 15px 40px → 12px 25px

**結果:**
```css
/* 占うボタン（メイン） */
.button {
    background: #D4C4B0;  /* ベージュ */
    padding: 25px 70px;
    font-size: 1.35em;
    font-weight: 700;
}

/* 共有ボタン（サブ） */
.share-button {
    background: #06C755;  /* LINE緑 */
    padding: 12px 25px;
    font-size: 0.95em;
    font-weight: 500;
}
```

#### 4. 画面高さの最適化

**問題:**
- スマホで共有ボタンが画面下に隠れてスクロールが必要

**解決策:**
- 全体の余白を詰めて高さを削減（約70-80px削減）
- **100vhは使わない**（コンテンツ量が可変なため）
- 必要な場合は自然にスクロールできるように

**削減箇所:**
```css
/* デスクトップ */
h1 { margin-bottom: 40px → 30px; }
.content-box {
    padding: 60px 40px → 50px 35px;
    min-height: 400px → 350px;
}
.button { margin-top: 40px → 30px; }

/* スマホ (600px以下) */
h1 { margin-bottom: 25px → 20px; }
.content-box {
    padding: 30px 20px → 35px 20px;
    min-height: 300px → 280px;
}
```

**100vhを使わなかった理由:**
- 運勢テキストの長さが異なる
- デバイスの高さもバラバラ
- 固定すると長いテキストが見切れるリスク
- 自然なスクロール体験を維持

#### 5. ボタンフローの改善

**問題:**
- 最初の画面に「公式アカウントに共有」ボタンがある
- まだ占ってないのに共有ボタンが見える

**解決:**

**最初の画面:**
- 「今年の運勢を占う」ボタンのみ表示

**結果画面:**
- 「もう一度占う」ボタン（占うボタンのテキスト変更）
- 「公式アカウントに共有」ボタンが出現

**実装:**
```javascript
function showFortune() {
    // 結果表示
    contentBox.innerHTML = `...`;

    // ボタンテキストを変更
    button.textContent = 'もう一度占う';

    // 共有ボタンを表示
    shareButton.classList.add('visible');
}
```

#### 6. 運勢バリエーションの拡張（10個 → 15個）

**問題:**
- 10個だと同じ運勢が出やすい（確率10%）
- 友達と被りやすくて話題性が低い

**解決:**
- 5個の新しい運勢を追加（合計15個に）
- 同じ運勢が出る確率: 10% → 6.7%に低下

**追加した運勢:**
1. **好きな音楽に出会えそう** (12文字)
2. **小さな幸せを見つけられそう** (14文字)
3. **人に優しくできそう** (10文字)
4. **新しい趣味が見つかりそう** (13文字)
5. **ラッキーな偶然が増えそう** (13文字)

**画像の最適化:**
- 新規画像5枚もPNG → JPEG変換（品質70）
- 合計: 11.8MB → 1.7MB (86%削減)
- 全画像合計サイズ: 約6.2MB（快適に読み込める）

#### 7. テキストの改行最適化

**問題:**
- スマホで長い文章が読みにくい

**解決:**
- 15-18文字/行を目安に改行
- 意味のまとまりで空行を挿入
- リズム感のある読みやすいレイアウト

**改善例:**
```

今年は春夏秋冬、たくさんアイスが食べられるでしょう。お気に入りアイスを見つけたら、私にも教えてね〜！

【変更後】
今年は、春夏秋冬
いろんなアイスに出会えそう。

お気に入りを見つけたら、

```

## 2026/01/01 午前 - フォント最適化と画像圧縮

### 概要

ユーザーフィードバックを基に、スマホでの読みやすさとページ読み込み速度を改善しました。

---

### ユーザーからの声

**問題点**:
1. 「文字が小さくて見えない」
2. 「友達登録めんどくさい」
3. 「何これ」「へえ」← あまり響かなかった様子

**解釈**:
- スマホでの視認性が悪い
- アプリの起動が遅い（画像が重い）
- コンテンツの魅力が伝わりきっていない

### 実施した改善

#### 1. フォントサイズの拡大

**変更内容:**

| デバイス | 変更前 | 変更後 | 拡大率 |
|---------|--------|--------|--------|
| **デスクトップ** | 1.1em | 1.3em | +18% |
| **スマホ (600px以下)** | 0.95em | 1.2em | +26% |
| **小画面 (400px以下)** | 0.9em | 1.1em | +22% |

**コード変更:**
```css
/* デスクトップ */
.fortune-text {
    font-size: 1.3em;  /* 1.1em → 1.3em */
    line-height: 2;
}

/* スマホ (600px以下) */
@media (max-width: 600px) {
    .fortune-text {
        font-size: 1.2em;  /* 0.95em → 1.2em */
        line-height: 1.9;
    }
}

/* 小画面 (400px以下) */
@media (max-width: 400px) {
    .fortune-text {
        font-size: 1.1em;  /* 0.9em → 1.1em */
    }
}
```

**結果:**
- ✅ スマホで運勢テキストがはっきり読める
- ✅ 高齢者や視力の弱い人にも配慮

---

#### 2. 画像の圧縮・最適化

**問題:**
- 各画像が 2.4〜2.7MB と超重量級
- 合計 27MB でページ読み込みが遅い
- モバイル回線では起動に20秒以上かかる

**解決方法:**
macOSの標準ツール `sips` を使用してPNG → JPEG変換

```bash
# 圧縮コマンド
sips -s format jpeg -s formatOptions 70 "01.png" --out "01.jpg"
```

**圧縮結果:**

| 項目 | 変更前 | 変更後 | 削減率 |
|------|--------|--------|--------|
| **形式** | PNG | JPEG (品質70) | - |
| **1枚のサイズ** | 2.4〜2.7MB | 364〜453KB | **約83%削減** |
| **合計サイズ** | 約27MB | 約4.5MB | **約83%削減** |

**パフォーマンス改善（推定）:**

| 回線速度 | 変更前 | 変更後 | 改善率 |
|---------|--------|--------|--------|
| **4G (10Mbps)** | 約22秒 | 約3.6秒 | **約6倍速** |
| **WiFi (50Mbps)** | 約4.3秒 | 約0.7秒 | **約6倍速** |

**コード変更:**
```javascript
// 画像パスを .png → .jpg に変更
const fortunes = [
  {
    title: 'たくさんのアイスに出会えるでしょう',
    image: 'images/01.jpg',  // .png → .jpg
    text: '...'
  },
  // ...
];
```

---

### 技術的な学び

#### sipsコマンドの使い方

**基本構文:**
```bash
sips -s format jpeg -s formatOptions [品質] [入力] --out [出力]
```

**品質の目安:**
- `100`: 最高品質（ファイルサイズ大）
- `70`: 良好な品質とサイズのバランス ← 今回採用
- `50`: やや画質劣化、サイズ最小

**一括変換例:**
```bash
for f in 01.png 02.png 03.png; do
  sips -s format jpeg -s formatOptions 70 "$f" --out "${f%.png}.jpg"
done
```

---

#### 画像最適化のベストプラクティス

1. **Web用画像は JPEG が基本**
   - 写真 → JPEG（今回のケース）
   - イラスト、ロゴ → PNG または SVG
   - アニメーション → WebP または GIF

2. **品質設定の目安**
   - 品質70〜80: Webで十分な品質
   - ユーザーは圧縮をほぼ気づかない
   - ファイルサイズは元の10〜20%に削減可能

3. **モバイルファーストの重要性**
   - モバイルユーザーが多い場合、ページ読み込み速度は最優先
   - 1秒遅延 = コンバージョン7%減少（Google調査）

## 2025/12/31 - LIFF URLとVercel URLの違い

### 概要

LIFF URLを使わずにVercel URLを直接開くと、LIFFが正しく認識されず「メッセージ送信の権限が許可されていません」エラーが発生する問題を解決しました。

---

### 発生した問題

**症状:**
- LINEアプリ内でVercel URL（`https://fortune-app-jet.vercel.app/`）を直接開く
- 「この機能はLINEアプリ内でのみ利用できます」エラーが表示される
- `isInClient: false` と表示される（LINEアプリ内なのに）

---

### 原因

**Vercel URLとLIFF URLの違い:**

| 開き方 | URL形式 | 結果 |
|--------|---------|------|
| ❌ Vercel URL直接 | `https://fortune-app-jet.vercel.app/` | LIFFとして認識されない |
| ✅ LIFF URL | `https://liff.line.me/2008804421-qXBqLT62` | LIFFとして正しく認識される |

**なぜVercel URL直接だとダメなのか:**
1. LINEアプリ内ブラウザで開いても、LIFF URLを経由しないとLIFFの認証フローが正しく動作しない
2. `liff.sendMessages()` は LIFF として認証された状態でないと権限エラーになる

---

### 解決方法

**LIFF URLで開く:**

```
❌ 間違い: https://fortune-app-jet.vercel.app/
✅ 正解:  https://liff.line.me/2008804421-qXBqLT62
```

**LIFF URLの構造:**
```
https://liff.line.me/[あなたのLIFF_ID]
```

**このプロジェクトのLIFF URL:**
```
https://liff.line.me/2008804421-qXBqLT62
```

---

### 学んだこと

1. **LIFF URL経由で開く**: 直接Vercel URLを開かず、必ず `https://liff.line.me/LIFF_ID` 形式で開く
2. **エンドポイントURL設定は変更不要**: LINE Developers ConsoleのエンドポイントURLは `https://fortune-app-jet.vercel.app/` のままでOK
3. **デバッグ情報を出力する**: `isInClient`、`isLoggedIn` などの値をログに出力しておくと問題特定が早い
